# Working on this repository

Meta-research studies designed, run and reviewed by language models, published as a Quarto site
with the whole trail intact. The studies are not the point on their own; **the trail is the
point**. A number that cannot be rederived does not belong here.

Read `README.md` for the build commands and `methods.qmd` for the published search protocol.

## House style, enforced everywhere

Prose here is generated by several different models and the site has to read as one voice.

- **Never use a dash as a sentence connector or parenthetical.** No em dash, no en dash, no
  spaced hyphen, no double hyphen. Use a semicolon, a colon, or a period. Hyphens inside
  compound words, code identifiers, file names and proper names are fine.
- **American spelling**: modeling, standardize, behavior, summarize, dichotomization.
- No hedging filler. A page states a fact about the literature, not an impression of it.
- **Never invent a citation.** An invented citation is the worst thing that can go in a project
  about research integrity and the easiest for a reader to catch. If a work cannot be resolved,
  say so and cite nothing.

## Analyses are written in R

Every analysis in every proposed meta-research study is written and executed in R, not Python.
Python is for the harvest and the site build only. A study directory carries its R code, its
data and its output so a reader can rerun it rather than trust it.

## Peer review

Each study is reviewed independently by models from different providers, given the study and
instructed to refute it.

| reviewer | invocation |
|---|---|
| ChatGPT | `codex exec -m gpt-6-astra -c model_reasoning_effort=max` |
| Grok | `grok --model grok-4.6 --reasoning-effort xhigh` |

`gpt-6-astra-max` is not a model id; the model is `gpt-6-astra` and the effort is a separate
setting. `~/.codex/config.toml` already defaults to `xhigh`, so the flag is only needed to reach
`max`.

**No study is reviewed by one model.** A study waits until every reviewer is available rather
than publishing with a one-reviewer history. The Codex account's usage limit was exhausted on
2026-09-16 and resets 2026-09-20; reviews do not run before then.

## Invariants that will silently break the site

1. **`landscape.qmd` and `corpus.qmd` are generated and must never be hand edited.**
   `build/render_site.py` overwrites both from `data/lit/map.json` and
   `data/lit/records-labelled.jsonl`. CI regenerates them and fails on any diff, which is the
   only guard against a hand-corrected statistic reaching the site.
2. **`styles.scss` must appear in both the light and dark theme lists** in `_quarto.yml`.
   Quarto emits one stylesheet per mode, so a rule listed only under light does not exist in
   dark.
3. **`data/lit/records.jsonl` is tracked; `data/lit/_cache/` is not.** The site rebuilds on a
   fresh clone without touching NCBI. Deleting the corpus means a full re-harvest.
4. **A navbar entry pointing at a file that does not exist fails the render.** Generated pages
   join the navbar only once they exist.

## Things that are true and easy to get wrong

- **A large hit count is not automatically a broken query.** `"trial registration"` returns
  156828 PubMed records, and the obvious diagnosis, that PubMed broke the phrase into words and
  ANDed them, was wrong: the quoted form returns fewer records than `trial AND registration`, so
  it is phrase-indexed. The real cause is that **Trial registration** is a structured abstract
  section label carried verbatim by every registered trial. Test the two forms against each
  other before concluding anything about a phrase.
- **Run `--counts` before harvesting anything.** It costs a few minutes and it is what exposed
  the above. A block sized after it has been downloaded is a block downloaded twice.
- **A tier B topic phrase retrieves studies that did the thing, not studies about it.** No
  boolean query separates them. That is a classification problem for a later stage, not a query
  to be tuned.
- **NCBI returns at most 9999 ids per query.** `collect_ids` bisects the publication-date range
  recursively until every part is under the ceiling, and records any single day still over it in
  `gaps` rather than truncating silently. The sibling project stops at month granularity and can
  truncate without saying so; do not copy that behavior back.
- **The efetch cache is keyed on the content of each batch, not its position.** Position keying
  is wrong the moment a query changes, and the failure is silent because every printed count
  comes from esearch and stays correct while the parsed records go stale.

## Sibling projects

`TTE-open-problems` and `ITC-open-problems` are the same author's audited catalogs of open
methodological problems, and this repository's harvester, theme and CI are adapted from TTE.
Worth reading before building a new stage here, particularly `build/adjudicate.mjs`, which turns
independent auditor opinions into a published verdict by a fixed rule, and its CLAUDE.md section
on how generated study code fails. Every defect it lists was silent.

Do not copy `render_site.mjs`, `adjudicate.mjs` or `build/studies/` wholesale. They encode TTE's
eighteen category codes and its problem-registry schema, neither of which exists here.
